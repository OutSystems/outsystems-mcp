Legacy Modernization Toolkit

Modernize into high‑quality apps with a top-class UI, at high fidelity, with minimal human intervention

AI agents read the legacy source, build the new app on OutSystems, then test and fix it until it passes. Your team makes two decisions, validating the requirements and picking the design, and reviews the result.

  • High fidelity. Every requirement comes from the code and cites the lines it came from, so the new app keeps the old rules.
  • Top-class UI. A modern design you choose, built from standard OutSystems UI blocks and matched screen by screen.
  • High quality, proven. 95% of requirements and 95% of the design, or it goes back to the build, with a test for every requirement.
  • Minimal human intervention. Agents build, test and fix on their own. You validate the requirements, approve the design and review the result.
Open source, MIT licence Builds on OutSystems Developer Cloud with Mentor

Overview

An app is done when it meets 95% of its requirements and matches 95% of its approved design

Anything short goes back to the build, with the list of what failed. After the fifth round, what still fails is reported as a gap.

Requirements gate
95%

Design gate
95%

Fix rounds per gate
5

Specialist roles
6
planner, designer, developer, reviewer, tester, reporter
What you get at the end.
  • A running app on your OutSystems tenant, built in small published steps you can open as it grows.
  • A Business Specification of what the legacy app does, in business terms.
  • An Implementation Report that traces each requirement to what was built.
  • A test toolkit alongside the report. The same checks the agent ran while building the app, as automated browser tests your team can re-run, one per requirement, with traces and screenshots of each run.
What it needs.
  • An OutSystems Developer Cloud tenant with Mentor available to the AI agent.
  • Legacy extraction enabled on that tenant for the source language. Lotus Notes is on by default; other languages are enabled on request.
  • A frontier AI model for generation. Smaller models finish too, with more cleanup.

How it works

From legacy source to a verified app

Five stages and three loops. You validate the requirements and choose the design before any screen is built. The app is tested and fixed after every published step, and a failed gate sends it back to the build.

1 · ExtractReads the source and writes down what the app does: data, screens, rules and roles, each traced to its file.You validate the requirementsRequirements collection and Business Specification
2 · DesignDraws design options for the new app's screens, in Figma or as HTML mockups.You pick the designThe approved design the gates check against
3 · GenerateBuilds on the tenant through Mentor, one small piece at a time. publish → test → fix, every piece A running app that grows step by step
4 · VerifyDrives the app in a browser against every requirement, then compares each screen with the design.Two scores against the 95% bar, with any gaps listed
5 · Hand overWrites the Implementation Report and packages every test run during the build into a toolkit your team can re-run.Implementation Report and re-runnable test toolkit

Each stage hands the next one a reviewable file, so you can stop, check and resume.

a gate fails → back to Generate with what failed, up to 5 rounds
a design problem found while building → back to Design, with the same checks
Human gates. Extraction and the build are separate commands, so you check the extracted requirements and correct anything missing or wrong before the build starts. No screen is built until you pick a design, and you can ask for changes first. The app, its data model and seed data can start while you choose. Back to design. If Generate or Verify finds the design can't work as drawn (a missing screen, a rule it can't show), the designer extends or revises it in the style you picked, and the new screens pass the same reviewer and tester checks as the first ones. Inner loop. After each published piece the agent opens the app, checks it and fixes it before moving on. Outer loop. Below 95% on requirements or design, the failures go back to Generate and Verify runs again, up to 5 rounds. After that, what still fails is listed as a gap in the report. With no design to score against, the design gate is skipped and the report says why. Nothing is lost. Every check from both loops ends up in the test toolkit, so you can re-run it after your own changes.

Commands

One command for each job

In Claude Code and Cursor, type the command. In Codex and Kiro, which have no plugin commands, ask the agent to follow the command's file in the plugin's commands folder. Either way, the agent runs that workflow with the skills above.

/extract-requirementsTurn legacy source into requirementsReads the code you upload and publishes the requirements collection and the Business Specification, every item cited to its source lines.
/generate-design-optionsDesign the migration onlyAbout three options, a pause for a pick, then the design gate on the picked option. Does not build or publish.
/workflow-legacy-appRun a full migrationDesign options and your pick, the build on your tenant, both 95% gates with their fix rounds, then the Implementation Report and the re-runnable test toolkit.
/how-it-worksExplain the toolkitBuilds this page, or answers one question about the toolkit with the matching section.
